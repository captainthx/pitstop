## Strengths

- The architecture follows the central acceptance contract: init parses its final generated bytes; validate/list/doctor use `config.Load`; run loads both original and captured config before preparing execution and shares `ApplyOverrides` with validate. Invalid inputs return a zero config. Schema v2, envelope v1, the Go floor and the runtime dependency set are preserved.
- The file reader uses an opened root and no-follow/nonblocking open, checks the opened descriptor, and bounds reads. Generic JSON checks precede migration/shape/semantic checks. Byte/depth, Unicode, duplicate keys, unselected checks, selection, text and aggregate limits have substantial regression coverage.
- Init uses exclusive creation and retains every created destination on persistence failure/cancellation. The installer verifies staging, authenticates exact trusted manifests and every listed file, rejects extras/symlinks, retains the original until staging completes, rolls back failed publication, and blocks re-entry with retained backup state.
- The portable assets are one source for both presets and installed resources. The skill distinguishes configuration validity, prerequisites and execution; it treats repository instructions as data and avoids inventing checks or deployment scope.
- The evidence separates 14 cases / 23 actual evaluator attempts from four selected runtime toolchains. Failed trials, earlier gate failures, unavailable tooling, and remote/native-platform gaps remain visible. The smoke generates its four runtime configs from canonical presets, uses isolated Python assertions, and checks real envelopes and step statuses.

### Important (Should Fix)

1. **[P2] Reject wrong containers before the ordered shape scan loses its position.**
   - `internal/config/parse.go:355-358`, `:382-385`, `:411-414` return success for a wrong opening token, although their caller treats the nested value as consumed. `Parse` then returns scanner errors directly at `:57-58`.
   - Reproduced against the final binary, SHA-256 `1092fde138cb5896f83d3416ca7ecee6d2476c205217e2da158c2d6e27a05f4a`, in a temporary empty Git repository: replacing a valid config's runner with `[]` produces `FILE_INVALID` at an empty path; replacing it with `["SECRET_COMMAND"]` produces `JSON_UNKNOWN_FIELD` at `/SECRET_COMMAND`. The array value is exposed as if it were a field name. `checks:{"private":"SECRET"}` and an object-valued `steps` also produce wrong paths; array-valued check elements fall back to `FILE_INVALID`.
   - All these inputs are rejected, but the promised typed, field-specific, value-free diagnostic contract is broken. An agent cannot repair the actual field reliably and config values can enter logs via issue paths.
   - Return a trusted `JSON_TYPE` issue at the expected container path before scanning inside it, or explicitly consume wrong values before the shape layer reports them. Cover wrong primitive/null/object/array values at `/runner`, `/checks`, `/checks/0`, `/checks/0/steps`, and `/checks/0/steps/0`. Assert zero Config, `errors.As(..., *ValidationError)`, exact path/code, one CLI envelope, and absence of a distinctive secret value.

2. **[P2] Enable Corepack shims before invoking the pnpm and Yarn Berry executables.**
   - `internal/agentassets/bundle/assets/examples/node-pnpm.json:6-8` and `node-yarn-berry.json:6-8` call only `corepack install --global ...` before bare `pnpm`/`yarn` commands. The analogous Classic bootstrap is at `node-yarn-classic.json:6`.
   - Focused offline inspection of the already-present `node:22-bookworm` image found no `/usr/local/bin/pnpm`; `/usr/local/bin/yarn` resolves to `/opt/yarn-v1.22.22/bin/yarn`. Corepack's own `enable --help` describes shim creation, and its shipped `InstallGlobalCommand` implementation only downloads/caches the manager and activates a default. It does not invoke shim creation. Thus pnpm remains unavailable and the Berry starter invokes Yarn 1 despite bootstrapping Yarn 4.
   - This is a starter defect even with the documented lockfile/packageManager/check-script prerequisites satisfied. The four-toolchain npm runtime result and the mapping-only trials do not exercise these paths.
   - Add the appropriate `corepack enable` operation or consistently invoke managers through Corepack. Keep the version pin and lockfile behavior. Check all three canonical Node manager starters for consistency; the bundle search found these bootstrap commands only in the three example assets, with prerequisite descriptions in `references/config-reference.md` and `references/examples.md`. Preserve trial artifacts as historical observations. Refresh the current manifest, retain the exact bdeb767 manifest and assets as trusted history for force upgrades, and add a focused actual pnpm/Berry bootstrap/version check with a small valid fixture. No repeat of unrelated toolchains is needed.

3. **[P2] Keep syntax-error JSON detection consistent with Cobra's parsed flags.**
   - `internal/cli/root.go:111-128` omits `--agent` and `--scope` from value-taking flags and recognizes only lowercase `false` as a false boolean value. The command-name fallback at `:72` duplicates the incomplete value-flag list.
   - Reproduced: `skill install --agent --json --scope project --repo <repo> --bad` emits JSON even though `--json` is the value consumed by `--agent`, not an output flag. `validate --json=0 --bad` and `validate --json=FALSE --bad` also emit JSON, whereas Cobra accepts those false spellings (`version --json=0` and `version --json=FALSE` both produce normal human output and exit 0).
   - Error output switches protocols unexpectedly for callers. Prefer the parsed flag value where available, and make the fallback consume every known value-taking flag and use the same boolean grammar as Cobra. Add syntax-error cases for both newly introduced string flags and supported false spellings.

4. **[P2] Preserve cancellation precedence during project-scope skill repository resolution.**
   - `internal/skill/install.go:94-97` returns `destination` errors before checking the context; project resolution is performed at `:275-277`. The next context check is only at `:193`, after several filesystem operations, and dry-run returns at `:141-142` before reaching it.
   - Reproduced with the exact final binary and an isolated synchronized fake Git: wait until repository resolution begins, send SIGINT to Pitstop, then let Git fail. `skill install --agent codex --scope project --repo <repo> --json` exits 2 with `SKILL_INSTALL_FAILED` / `could not resolve project repository`, rather than the specified 130 / `CANCELLED`. No destination is installed.
   - Init and validate already handle this boundary. Check cancellation immediately after destination resolution, before returning its error or reporting a dry-run success, while retaining the established post-publish success ruling. Add deterministic success/failure Git-resolution cancellation tests with release/cleanup on every test path.

5. **[P2] Escape untrusted filesystem text in human diagnostics and recovery output.**
   - `internal/skill/install.go:124` and `:155` append an untrusted retained-backup path directly to the error message. `internal/report/report.go:36` renders it unchanged; the new result summaries at `:76`, `:87`, and `:98` also render paths directly.
   - Reproduced in a temporary Git repo by creating `.agents/skills/.pitstop-config.backup-` followed by ESC color-control bytes and a harmless marker. A human-mode dry-run prints those raw ESC bytes in the recovery error. A repository can supply such a filename without a concurrent same-user attacker or any executable project code.
   - This violates the stated filename/terminal-control trust boundary and can manipulate the user's diagnostic display. Escape control/format characters in human-facing paths/messages and bound displayed recovery text without changing the actual path used by filesystem operations or truncating machine-readable path fields. Cover recovery filenames and repository paths, and preserve useful recovery location information. Review the common human error/result path so the fix is applied consistently rather than only at this one concatenation.
