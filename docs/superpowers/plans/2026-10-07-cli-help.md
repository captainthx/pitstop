# CLI Help Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ผู้ใช้ดูฟีเจอร์ คำสั่ง flags และตัวอย่างการใช้ Pitstop ได้จาก `pitstop -h` และ help ของแต่ละคำสั่ง โดยไม่ต้องเปิด docs เพื่อค้นหาวิธีใช้เบื้องต้น

**Architecture:** ใช้ระบบ help ของ Cobra ที่ติดตั้งอยู่แล้ว เติม `Short`, `Long`, `Example` ใน command constructors เดิม ไม่สร้าง help renderer หรือ parser ใหม่ Cobra จะสร้างรายการคำสั่งและ flags จาก command definitions ปัจจุบัน

**Tech Stack:** Go 1.26.5, Cobra v1.10.2, Go testing package

**Spec:** ข้อ 1 ของข้อเสนอในแชตนี้: เติมคำอธิบาย ฟีเจอร์ และตัวอย่างให้ help ของ CLI โดยใช้ Cobra เดิม ผู้ใช้ขอแผน implement เฉพาะข้อนี้ รายละเอียดที่ต้องใช้ทั้งหมดอยู่ในเอกสารนี้

## Global Constraints

- ทำเฉพาะ help: ไม่รวม installer, release workflow, คำสั่งใหม่ หรือการเปลี่ยน runtime behavior
- ไม่เพิ่ม dependency และไม่เปลี่ยนชื่อ flags, ค่า defaults, JSON schema หรือ exit codes เดิม
- ใช้ภาษาอังกฤษใน CLI ให้สอดคล้องกับข้อความปัจจุบัน; README มีภาษาอังกฤษและไทย
- `-h`, `--help`, `help <command>` ใช้ระบบมาตรฐานของ Cobra
- Help เป็นข้อความบน stdout และสำเร็จด้วย exit code 0 แม้ใช้ร่วมกับ `--json`; ไม่สร้าง JSON help API
- Help ต้องเปิดได้โดยไม่ต้องมี `.pitstop.json`, Git repository, act หรือ Docker ที่พร้อมใช้งาน
- ทุก shell command ในการ implement ต้องขึ้นต้นด้วย `rtk` ตาม `/Users/thanyatab/.codex/RTK.md`

## Review Focus

1. เรียก `pitstop` โดยไม่มี arguments: เห็นภาพรวมและคำสั่ง ไม่เริ่มรัน checks
2. ใช้ `-h` เทียบกับ `--help`: ได้เนื้อหาเดียวกันทั้ง root และแต่ละ command
3. ใช้ `pitstop help run`: ได้ help ของ run รวมตัวอย่างและ flags
4. ใช้ help กับ repo ที่ไม่มีอยู่และ PATH ว่าง: ไม่เรียก runtime tools และยังคืน 0
5. ใช้ `run --json -h`: ได้ human help บน stdout, stderr ว่าง และไม่เริ่มรันงาน

ทุกข้อมีกรณีทดสอบใน Task 1 ใช้ substring assertions ไม่ล็อก whitespace หรือ snapshot ทั้งหน้า

```go
func TestHelp(t *testing.T) {
    t.Setenv("PATH", "") // Help must not launch Git, act, or Docker.
    missingRepo := t.TempDir() + "/missing"
    tests := []struct {
        name string
        args []string
        want []string
    }{
        {"root", []string{"-h"}, []string{
            "Run GitHub Actions checks locally before sending changes to CI.",
            "uncommitted changes", "reports and logs", "Ctrl+C",
            "Check repository, configuration, workflow, act, and Docker readiness",
            "List workflow jobs, selection, and eligibility",
            "Run selected workflow jobs in an isolated working-tree copy",
            "Show version and build information", "--repo", "pitstop run --repo /path/to/repo",
        }},
        {"doctor", []string{"doctor", "-h"}, []string{
            "act 0.2.89", ".pitstop.json", "pitstop doctor --repo /path/to/repo", "--json", "--repo",
        }},
        {"list", []string{"list", "-h"}, []string{
            "blocked", ".github/workflows/ci.yml", "pitstop list --repo /path/to/repo", "--json", "--repo",
        }},
        {"run", []string{"run", "-h"}, []string{
            "already selected in .pitstop.json", "Ctrl+C", "reports and logs",
            "pitstop run --repo /path/to/repo --job lint --job test",
            "--job", "--timeout", "--arch", "--force-integration", "--json", "--repo", "20m0s",
        }},
        {"version", []string{"version", "-h"}, []string{
            "Show version and build information", "pitstop version --json", "--json",
        }},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            var shortOut, shortErr, longOut, longErr bytes.Buffer
            if code := Execute(tt.args, &shortOut, &shortErr); code != 0 {
                t.Fatalf("exit=%d stderr=%s", code, shortErr.String())
            }
            longArgs := append([]string(nil), tt.args...)
            longArgs[len(longArgs)-1] = "--help"
            if code := Execute(longArgs, &longOut, &longErr); code != 0 {
                t.Fatalf("long help exit=%d", code)
            }
            if shortErr.Len() != 0 || longErr.Len() != 0 || shortOut.String() != longOut.String() {
                t.Fatal("help aliases must produce identical stdout and empty stderr")
            }
            for _, want := range tt.want {
                if !strings.Contains(shortOut.String(), want) {
                    t.Errorf("help missing %q", want)
                }
            }
        })
    }
    for _, args := range [][]string{
        {},
        {"help", "run"},
        {"doctor", "--repo", missingRepo, "-h"},
        {"run", "--repo", missingRepo, "--json", "-h"},
    } {
        var out, errOut bytes.Buffer
        if code := Execute(args, &out, &errOut); code != 0 || errOut.Len() != 0 {
            t.Fatalf("args=%v exit=%d stderr=%s", args, code, errOut.String())
        }
        want := "Run GitHub Actions checks locally before sending changes to CI."
        if len(args) > 0 {
            want = "pitstop " + args[0] + " --repo /path/to/repo"
            if args[0] == "help" {
                want = "pitstop run --repo /path/to/repo"
            }
        }
        if !strings.Contains(out.String(), want) || !strings.Contains(out.String(), "Usage:") {
            t.Fatalf("args=%v missing help: %s", args, out.String())
        }
    }
}
```

  - Run selected jobs sequentially through act and Docker.
  - Test an isolated working-tree copy, including uncommitted changes.
  - Read human or JSON results and retain reports and logs.
  - Set per-job timeouts, cancel with Ctrl+C, and prevent overlapping runs.

Running checks requires Git, act 0.2.89, and a reachable Docker daemon.

## Acceptance Criteria

- `pitstop -h` บอก purpose, ฟีเจอร์หลัก, prerequisites, คำอธิบายคำสั่ง และเส้นทางเริ่มใช้
- help ของ `doctor`, `list`, `run`, `version` มีคำอธิบายและตัวอย่างที่ตรงกับพฤติกรรมปัจจุบัน
- `run -h` อธิบาย configured job IDs, timeout ต่อ job, architecture override, JSON streams และขอบเขต integration adapter
- Help เปิดได้โดยไม่มี repo/config/runtime tools; exit 0 และ stderr ว่างสำหรับกรณีที่ทดสอบ
- Tests เดิมยังผ่านและ runtime/JSON behavior ไม่ถูกเปลี่ยน
